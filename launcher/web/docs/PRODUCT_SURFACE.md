# Web 产品呈现

本页说明 Launcher 提供哪些界面和操作，以及游戏能力如何进入界面。具体作品的状态见[项目进度](../../../docs/TOUHOU_PROGRESS.md)；接入操作见[新游戏接入](ADAPTING_A_GAME.md)。

## 产品声明和实际可用性

作品身份、普通/多人入口、保存规则、难度与机体组合、可选功能来自根 `contracts/src/product-catalog.mts`。Runtime Release、站点资源和本地安装状态决定这次启动实际能用什么。界面只展示这些声明与真实状态，不维护第二份逐作能力表。

可以从项目根查看某作当前登记：

```text
npm run adapter:inspect --workspace @eagler/web -- --game=th15
```

报告包含产品、资源准备和协议，不代表该作已经通过玩法或设备验收。TH15 当前没有多人入口；TH09 的对战卡片和观战播放器有独立呈现，实验状态需要与正式已发布能力区分。

目录项从普通产品与已声明的多人入口派生。`testBuild` 只启用产品表标记 `testOnly` 的测试产品；不能因为字段缺失、为 false 或站点元数据暂时失败而隐藏 TH10 等普通正式作品。静态/无 JavaScript 呈现与实际 React 目录应使用同一产品声明。封面资源由 Host artwork 处理，目录不维护第二份卡片名单。

## 共用界面

| 界面 | 用户可以做什么 |
| --- | --- |
| 游戏目录 | 选择作品、查看资源与入口状态、开始普通或支持的多人模式 |
| 资源管理 | 下载、安装、更新、导入本地 Package 或声明的原版 DATA |
| 游戏设置 | 保存当前作品偏好；只提供 Runtime 支持的选项 |
| 存档与 Replay | 查看、导入、导出和删除允许的用户文件；使用实际 Runtime 文件接口 |
| 游戏播放器 | 启动、退出、重启、触控、放大镜和必要状态反馈 |
| 多人房间 | 创建/加入、席位、难度/机体、准备、连接和支持的旁观 |
| 离线与更新 | 准备 App Shell/Runtime，保留可用安装代次，空闲时切换更新 |

房间人数、难度和机体范围来自产品声明。观战按钮必须有对应 Runtime 数据流；TH09 中途观战还需从已开赛房间进入的真实流程证据。不能只验证一张房间预览卡片。

## 设置的拥有者

触控布局编辑、放大镜、按钮显隐和目录交互由 Launcher 处理。游戏实际消费的触控模式、灵敏度、显示节奏、音乐解码和多人选项，经规范字段进入 `configure.options`。消息与约束见[接入协议](../../../docs/GAME_ADAPTER_CONTRACT.md)和[能力分类](../../../docs/ADAPTER_CAPABILITIES.md)。

原版菜单、暂停/继续、角色和规则仍属于游戏。合作模式的资源转移、幽灵救援等行为不能套到 TH09 的对战规则。新的游戏界面复用会话和资源流程，必要的作品特有呈现另有明确组件。

## 资源模式和故障反馈

Hosted、External、Import 共用目录和安装模型。远端获取失败后仍可主动导入本地包；未完成安装不能成为当前代次。游戏所需资源齐全后再启动 Runtime，`ready` 与 `first-frame` 分别处理。

语言和音乐同时受产品、实际 Runtime、站点及已安装组件约束。缺少可选资源时为当前启动选择可用回退，保留持久化偏好。显示错误指出资源、连接、Runtime 或存储阶段，不用游戏编号猜测失败原因。

## 验证

目录、设置和房间用当前组件测试，安装/更新与打包用实际资源闭包测试。可见布局、焦点、触控、离线和重载使用真实浏览器；方法见[开发与验证](DEVELOPMENT.md)。样式、文案和组件排版可以维护，不以完整 CSS 或旧 JSX 字节相同作为产品规则。
