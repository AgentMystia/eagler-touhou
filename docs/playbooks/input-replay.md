# 输入、Replay 与绘制

## 状态顺序

游戏固定逻辑步拥有输入边沿、RNG、计时、碰撞、脚本和音频事件。Web 显示刷新可以更快，额外 Draw 是否重复消费或推进状态须与原调用顺序对照，不能把原绘制路径预设为纯函数。插值端点必须跟随对象创建、复用、阶段切换和回滚恢复。

修改输入时，沿真实路径检查：浏览器键盘/触控拥有者 → Runtime 会话与消息验证 → 游戏输入采样 → 固定步 → Replay/联机确认。特别覆盖按住移动时打开 UI、失焦松键、重启、旧 epoch 消息和旁观者只读操作。

## Replay 的不同证据

- 原版单人 Replay 由各游戏解释，文件扩展名相同不代表多人记录兼容。
- common 的 `InputReplay` 保存已确认的全席位输入；格式与所有权见 [input-replay](../../eagler-common/docs/input-replay.md)。
- Replay Verifier 比较完整逻辑步后的明确状态字段；游戏适配器决定采集边界和字段语义。
- Presentation Lab 检查真实绘制路径、插值及逐字段兼容性；先区分原 draw 写入与新增刷新路径差异，运行高刷新率或设置一个“禁止推进”标志不能替代覆盖证据。

## 修改步骤

1. 先按[还原兼容对照](verification.md#还原兼容对照)固定来源与调用顺序，确定状态写入点、回滚/存档是否包含它，以及 draw 的写入和消费是否属于原行为。
2. 在当前生产对象或真实游戏入口复现；保留原始输入和失败帧，不靠放宽比较容差消除差异。
3. 对新建、对象池复用、暂停/恢复、场景切换及回滚补帧分别检查。
4. 对读取只读 Replay 的流程验证不会改写存档。文件操作结束后的重启须使用新会话，旧回调不能改变新游戏。
5. 运行公共 CTest、受影响作品测试和必要的浏览器验证，再更新能力表。

TH06/TH07 的 `void*` 参数回调和 `ReleaseSingleChain` 临时链存在于反编译来源。TH06 `DrawFpsCounter` 的统计写入、TH07 `clearBackground` / `isDarkening` 的 draw 清标记也是已核实的兼容事实，来源提交和函数入口见[还原兼容对照](verification.md#还原兼容对照)。这些事实不直接构成 bug，也不承诺 typed callback 迁移或搬移 draw 副作用。额外绘制与 Replay 状态覆盖仍需实际验证，见[审计](../ENGINEERING_AUDIT.md)。本轮没有重新执行全作品原版对照或完整长 Replay，不新增这类完成声明。
