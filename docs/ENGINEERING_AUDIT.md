# 工程审计与改进清单

## 范围与结论

本文是重构阶段记录，包含未提交、未发布的候选状态。日常游戏适配从[教程](ADAPTING_A_GAME.md)和[协议](GAME_ADAPTER_CONTRACT.md)开始，前端接入从 [Web 教程](../launcher/web/docs/ADAPTING_A_GAME.md)开始。

审计起点为主仓库 `74b2f12`，范围是 TH06—TH11、TH15、现有 Web Launcher、eagler-common，以及实际消费的协议、构建、资源、测试和交付组件。先检查实际源码、调用关系和原有检查结果，再整改、构建及运行，最后整理文档。

本轮已经完成主仓库重组、关键前端职责拆分、跨平台工程入口、独立网络服务、共享协议归位、旧测试门禁清理及文档重写。**这不等于七作全部玩法、多人链路和所有设备都已验收。** 后文明确列出已解决、保留理由、尚待整改和未执行的验证。

旧路径均指审计基线，可用 `git show 74b2f12:<path>` 复核主仓库原内容；游戏的旧路径在对应子仓库历史中查阅。当前路径相对所属组件：前端条目的 app、lib、src、scripts、tests 位于 launcher/web，游戏条目位于对应子模块；项目级路径相对仓库根目录。已退役文件保留在 Git 历史，不通过空白重定向页继续占据现行文档。

“已整改”表示对应工程问题已处理，并有本轮所列验证；“部分完成”仍有明确后续；“保留”是有实际消费者或兼容依据的设计决定；“未验收”表示证据缺口，不自动认定功能损坏。
